한 문장 던졌더니 게임이 나왔다 — Claude가 고양이 우주 슈팅게임을 만든 6단계 (프롬프트 전문)

일본 크리에이터 @550Atelier가 Claude에게 건넨 건 “고양이가 우주에서 싸우는 슈팅게임 만들어줘” 한 문장뿐이었어요(조회 99만). Claude는 안 쓴 90%를 먼저 채우고, 회색 네모로 재미부터 확인하고, 색에 역할을 주고, 손맛과 소리를 더한 뒤 봇으로 300판을 돌려 테스트했어요. 원작자는 “게임 이해력뿐 아니라 영상까지 잘 만든다”고 했는데, 제작 과정을 보여주는 이 영상도 Claude Code로 만든 거예요. 그 6단계를 그대로 따라 할 수 있는 프롬프트로 정리했어요.

  3. 33. 색에 역할 주기내 기체 따뜻한 색 · 적 차가운 색 · 적 총알 핑크 · 배경 어둡게

핵심은 “바로 완성본을 만들지 않는다”예요. 그림보다 재미가 먼저, 재미가 확인되면 보기 좋게, 보기 좋아지면 손맛과 소리, 마지막으로 테스트. 그리고 영상의 마지막 말처럼 재미있는지는 사람이 정해요. 이 순서를 프롬프트에 적어 주면 한 문장짜리 요청도 훨씬 게임다운 결과로 돌아와요.

준비물

  • Claudeclaude.ai 대화창이면 HTML 게임 하나는 충분해요. 원작 영상 끝에는 Claude Code가 표시돼 있어요.
  • 브라우저결과가 HTML 파일 하나라서 크롬에서 바로 플레이해요. 설치할 것 없음.

  • 10분단계마다 결과를 보고 “좋아, 다음”이라고 답하며 진행하면 돼요.

6단계 자세히

method
01STEP 11·2단계

1~2. 안 쓴 90%를 읽고, 네모로 먼저 논다

  • 입력은 이 한 문장이었어요. Claude는 “내가 만들게! 요령도 보여줄게”라며, 빙산처럼 문장 아래에 숨은 90%부터 채웠어요. 조작은 방향키, 첫 30초에 사로잡기, 보스를 쓰러뜨리면 승리, 3번 맞으면 패배, 브라우저에서 바로 플레이, 고양이는 귀엽게. 그리고 “스마트폰으로도 할까?”처럼 헷갈리는 것만 물어봤죠(원작자 답: 스마트폰도!).
  • 원작 입력 (일본어 그대로)
    ネコが宇宙で戦うシューティングゲームを作って
  • 같은 내용 한국어
    고양이가 우주에서 싸우는 슈팅게임을 만들어줘
  • 그다음 그림 없이 회색 네모(그레이박스)로 먼저 움직여 봤어요. “움직이고 → 쏘고 → 쓰러뜨리고 → 강해지고”가 한 바퀴 잘 돌면 그래픽이 없어도 재미있다는 걸 확인하고, 보상은 일부러 위험한 곳에 뒀어요. 너무 어려우면 불안하고, 너무 쉬우면 지루하니 그 사이(몰입 구간)를 맞추는 것도 이 단계예요.
  • TIP“그림은 나중에, 네모로 재미부터 확인해”라는 한 줄이 결과를 크게 바꿔요. 예쁜데 재미없는 게임을 피할 수 있어요.
02STEP 23단계

3. 색에는 역할이 있다

  • 재미가 확인된 뒤에야 그림을 그렸어요. 먼저 실루엣만 봐도 적과 나를 구분할 수 있게 하고, 색에 역할을 나눴어요.
    1. 1내 기체 = 따뜻한 색 (주황)
    2. 2적 = 차가운 색 (파랑·보라)
    3. 3적 총알 = 핑크 — 탄막이 쏟아져도 내 총알(노랑)과 안 헷갈려요
    4. 4배경 = 어둡게, 밝기 차이로 시선이 가야 할 곳을 안내
    5. 5그림자는 그냥 어둡게가 아니라 중간색으로 — 그래야 귀여워요
  • TIP내 게임에도 “누가 무슨 색인지” 표를 프롬프트에 먼저 적어 주면, 화면이 복잡해져도 읽기 쉬운 게임이 나와요.
03STEP 34·5단계

4~5. 손맛은 만들 수 있다, 모든 움직임엔 소리

  • “플레이는 되는데 밋밋하다”에서 손맛 장치를 하나씩 켰어요. 화면 흔들림, 히트스톱(맞는 순간 아주 짧게 멈춤), 파티클, 번쩍임. 무거운 공격일수록 더 크게, 더 길게. 전부 켜자 같은 장면이 확 “기분 좋은” 게임이 됐어요.
  • 소리도 같은 원칙이에요. 쏠 때, 맞힐 때, 강해질 때 전부 소리를 넣고, 같은 소리를 반복하지 않고 매번 조금씩 다르게 만들었어요.
  • 손맛 점검 프롬프트 (게임 받은 뒤 붙여넣기)
    [손맛 점검 — 게임을 받은 뒤 그대로 붙여넣기]
지금 게임에 아래가 다 들어갔는지 하나씩 확인하고, 빠진 건 추가해줘:
- 적을 맞히면 아주 짧게 멈추는 히트스톱
- 큰 폭발이나 피격 때 화면 흔들림 (설정에서 끌 수 있게)
- 맞은 자리의 파티클과 숫자(+100 같은)
- 피격 순간 하얗게 번쩍임
- 쏠 때·맞힐 때·강해질 때·질 때 각각 다른 소리, 매번 음높이 살짝 다르게
- 적 총알이 탄막 속에서도 눈에 잘 띄는 색인지
각 항목을 ON/OFF로 비교할 수 있는 토글도 화면 구석에 만들어줘.
04STEP 46단계

6. 버그는 적! 봇으로 300판 테스트

  • Claude의 작업 방식은 “만들고 → 움직이고 → 보고 → 고치고”의 반복이었어요. 판정이 어긋나거나 총알이 사라지지 않는 버그를 찾아 고치고, 자동 플레이 봇을 300판 돌려서 “여기서 다들 막힌다”는 구간(3번째 웨이브)을 찾아냈어요. 마지막엔 분신을 만들어 일부러 망가뜨려 보기까지 했죠.
  • 6단계 프롬프트 (한국어)
    고양이가 우주에서 싸우는 슈팅게임을 만들어줘. 브라우저에서 바로 플레이할 수 있는 HTML 파일 하나로.

바로 만들지 말고 아래 순서대로 진행해:
1) 내가 안 쓴 부분부터 정리해줘 — 조작법, 이기는 조건, 지는 조건, 첫 30초에 무엇으로 사로잡을지, 캐릭터 분위기. 헷갈리는 것만 나에게 물어봐.
2) 그림은 나중에. 회색 네모만으로 먼저 움직여 보고 “움직이기 → 쏘기 → 쓰러뜨리기 → 강해지기”가 재미있게 도는지 확인해. 보상은 위험한 곳에 둬.
3) 그다음 그림. 실루엣만 봐도 적과 나를 구분되게 하고, 색에 역할을 줘: 내 기체는 따뜻한 색, 적은 차가운 색, 적 총알은 핑크, 배경은 어둡게.
4) 손맛을 더해: 화면 흔들림, 히트스톱(맞는 순간 아주 짧게 멈춤), 파티클, 번쩍임. 무거운 공격일수록 더 크고 길게.
5) 모든 움직임에 소리를 넣어. 같은 소리를 반복하지 말고 매번 조금씩 다르게.
6) 직접 여러 번 테스트해: 자동 플레이 봇을 돌려서 어느 구간에서 다들 막히는지 찾고, 버그(판정 어긋남, 사라지지 않는 총알 등)를 고쳐.

마지막에 무엇을 바꿨는지 5줄로 정리해줘. 재미있는지는 내가 직접 해보고 말해줄게.
  • 같은 내용 영어
    Make a shooting game where a cat fights in space — a single HTML file I can play right away in the browser.

Don't build it all at once. Work in this order:
1) First fill in what I didn't say: controls, win condition, lose condition, how to hook the player in the first 30 seconds, the character's vibe. Only ask me about things you're unsure of.
2) Art comes later. Prototype with grey boxes and check that the core loop "move → shoot → defeat → power up" is fun. Put rewards in dangerous places.
3) Then the art. Make enemies readable by silhouette alone and give colors a role: player = warm, enemies = cool, enemy bullets = pink, background = dark.
4) Add game feel: screen shake, hit stop, particles, flashes. Heavier hits get bigger and longer feedback.
5) Give every action a sound. Don't repeat the exact same sound — vary it slightly each time.
6) Playtest a lot: run an auto-play bot to find where everyone gets stuck, and fix bugs (hitbox drift, bullets that never disappear, etc.).

At the end, summarize what you changed in 5 lines. I'll decide whether it's fun by playing it myself.
  • 주의그래도 재미있는지는 사람이 정해요. 원작 영상의 마지막 말도 “재미는 사람이 정한다”예요. 직접 해보고 “3번째 웨이브가 너무 어려워”처럼 구체적으로 말해 주세요.

[내 한 문장, 예: 햄스터가 부엌에서 칼을 피하는 게임] 을 만들기 전에, 내가 안 쓴 부분을 한 장짜리 게임 설계서로 채워줘. 코드는 아직 쓰지 마.
표로:
- 조작: [플랫폼, 예: PC 키보드 + 폰 터치]
- 코어 루프: 계속 반복되는 행동 4개 (예: 움직이기 → 피하기 → 줍기 → 강해지기)

02그레이박스 점검 — 재미부터 확인
설계서대로 그림 없이 회색 네모만으로 먼저 만들어줘. HTML 파일 하나로.
- 코어 루프 [코어 루프, 예: 움직이기→쏘기→쓰러뜨리기→강해지기]가 한 바퀴 도는지
- 보상(아이템·점수)은 일부러 위험한 곳에
- 화면 구석에 숫자 3개 표시: 생존 시간, 맞은 횟수, 얻은 점수
만든 뒤 1분 동안 플레이했을 때 지루해질 만한 순간과 너무 어려울 만한 순간을 각각 2개씩 예상해서 적어줘. 그림은 내가 「재미있어」라고 할 때까지 넣지 마.

원작 2단계를 점검표로 · 예쁜데 재미없는 게임을 피해요

03색 역할표 — 내 게임에 맞게
재미 확인이 끝났어. 이제 그림을 넣을 건데, 먼저 색 역할표를 정하고 적용해줘.
- 주인공: [색 계열, 예: 따뜻한 주황]
- 적: [예: 차가운 파랑·보라]
- 적 총알(위험한 것): [예: 핑크에 흰 테두리]
- 아이템·보상: [예: 노랑, 반짝임]
- 배경: 어둡게, 시선이 가야 할 곳만 밝게
색만으로 구분하지 말고 모양·밝기도 다르게 해서 색 구분이 어려운 사람도 알아보게 해줘.
적용한 뒤 역할 · 색 코드 · 모양 특징을 표로 보여줘.

원작 3단계 「색에는 역할이 있다」를 빈칸으로

04웨이브 설계 — 난이도 곡선 표
게임을 [웨이브 수, 예: 5]개 웨이브로 나눠서 난이도 곡선을 설계해줘. 아직 적용하지 마.
표로: 웨이브 · 적 종류와 수 · 적 총알 속도(느림/보통/빠름) · 새로 나오는 요소 하나 · 예상 클리어 시간
규칙:
- 새 요소는 한 웨이브에 하나만
- 어려운 웨이브 다음엔 숨 돌릴 웨이브 하나
- 마지막은 보스: [보스 아이디어, 예: 거대한 털뭉치 우주선]
표를 보여주고 내가 OK하면 적용해줘.

너무 어려우면 불안, 너무 쉬우면 지루 — 그 사이를 표로 맞춰요

05효과음 목록 — 파일 없이 코드로
게임의 모든 움직임에 들어갈 효과음 목록을 표로 만들고 적용해줘.
표로: 언제(쏘기·맞히기·피격·강화·보스 등장·게임 오버 등) · 느낌 · 길이(짧게/보통)
- 전체 느낌: [소리 분위기, 예: 귀엽고 통통 튀는 8비트]
- 같은 소리를 반복하지 말고 매번 음높이를 살짝 다르게
- 소리 파일 없이 브라우저에서 코드로 만든 효과음으로
- M 키(폰은 화면 버튼)로 음소거
적용 뒤 가장 자주 나는 소리 3개는 볼륨을 낮춰줘.

06봇 테스트 리포트 — 숫자로 받기
자동으로 플레이하는 봇을 만들어서 [판 수, 예: 300]판 돌려줘.
결과를 표로:
- 웨이브별 도달한 비율
- 많이 죽은 원인 상위 3개 (예: 어떤 적의 어떤 총알)

- 찾은 버그 목록 (판정 어긋남, 사라지지 않는 총알 등)

07내가 해본 느낌 전달 — 사람 플레이테스트
내가 직접 [판 수, 예: 5]판 해봤어. 느낌을 적을게.
- 재미있던 순간: [예: 보스 총알을 아슬아슬하게 피할 때]
- 답답했던 순간: [예: 아이템이 너무 빨리 사라짐]
- 난이도: [예: 2웨이브까지 너무 쉬움]
이 피드백으로 고칠 것 3개를 우선순위로 정리하고, 각각 무엇을 얼마나 바꿀지 숫자로 적어줘.
1번부터 하나씩 고치고, 고칠 때마다 바꾼 점을 한 줄로 알려줘.

원작의 마지막 말 「재미는 사람이 정한다」 · 막연한 「별로야」보다 훨씬 잘 고쳐져요

08마무리 — 시작 화면·기록 저장·공유 준비
게임이 완성됐어. 친구에게 보여줄 수 있게 마무리해줘.
- 시작 화면: 게임 제목 [게임 제목, 예: 우주 고양이 대작전], 조작법 한 줄, 시작 버튼
- 최고 점수를 브라우저에 저장해서 다음에 열어도 남게
- 게임 오버 화면에 점수와 「다시 하기」 버튼
- 일시정지(P 키, 폰은 화면 버튼)
게임 플레이 부분은 건드리지 마. 추가한 것만 목록으로 알려줘.

226단계 프롬프트 (영어)
Make a shooting game where a cat fights in space — a single HTML file I can play right away in the browser.

Don't build it all at once. Work in this order:
1) First fill in what I didn't say: controls, win condition, lose condition, how to hook the player in the first 30 seconds, the character's vibe. Only ask me about things you're unsure of.
2) Art comes later. Prototype with grey boxes and check that the core loop "move → shoot → defeat → power up" is fun. Put rewards in dangerous places.
3) Then the art. Make enemies readable by silhouette alone and give colors a role: player = warm, enemies = cool, enemy bullets = pink, background = dark.
4) Add game feel: screen shake, hit stop, particles, flashes. Heavier hits get bigger and longer feedback.
5) Give every action a sound. Don't repeat the exact same sound — vary it slightly each time.
6) Playtest a lot: run an auto-play bot to find where everyone gets stuck, and fix bugs (hitbox drift, bullets that never disappear, etc.).

At the end, summarize what you changed in 5 lines. I'll decide whether it's fun by playing it myself.

이럴 땐 이렇게

troubleshooting

자주 막히는 부분을 모았어요

Q코딩을 몰라도 돼요?
A

네. 결과가 HTML 파일 하나라서 받은 코드를 메모장에 붙여 .html로 저장하고 더블클릭하면 돼요. claude.ai에서는 대화창 옆 미리보기로 바로 플레이할 수도 있어요.

Q원작 영상도 Claude가 만들었어요?
A

원작자는 “게임 이해력뿐 아니라 영상 만들기까지 잘한다”고 썼고, 영상 마지막에 Claude Code가 표시돼요. 어떤 모델·설정을 썼는지는 공개되지 않았어요.

Q봇 테스트는 어떻게 시켜요?
A

“자동으로 플레이하는 봇을 만들어 300판 돌리고, 어느 구간에서 가장 많이 죽는지 표로 보여줘”라고 요청하면 돼요. Claude Code처럼 직접 실행할 수 있는 환경에서 더 잘 돼요.

Q스마트폰에서도 돼요?
A

6단계 프롬프트 1번에서 “스마트폰 터치 조작도”라고 적어 주면 돼요. 원작자도 그렇게 답했어요.

Q프롬프트는 어디에 붙여요?
A

claude.ai 대화창이나 Claude Code에 붙이세요. 원작 영상 끝에는 Claude Code가 표시돼 있어요. 봇을 실제로 돌리는 테스트는 코드를 직접 실행할 수 있는 Claude Code가 더 잘 맞아요.

QChatGPT로도 돼요?
A

네, 같은 프롬프트를 쓸 수 있어요. 다만 원작 결과는 Claude로 만든 거라 모델마다 결과가 달라질 수 있어요.

Q코드가 중간에 끊겼어요
A

답이 길면 중간에 끊길 수 있어요. 「끊긴 줄부터 이어서 끝까지 써줘」라고 보내거나, 「파일 전체를 다시 줘」라고 하세요.

Q게임이 안 움직이고 빈 화면이에요
A

「열었더니 빈 화면이야. 오류를 찾아 고친 파일 전체를 다시 줘」라고 보내세요. 메모장에 붙일 때 앞뒤가 빠지지 않았는지, 확장자가 .html인지도 확인하세요.

tips
  1. 1

    첫 문장은 “무엇이 · 어디서 · 어떤 게임” 세 가지만.

  2. 2

    그림보다 재미 먼저 — “네모로 먼저 확인해”를 꼭 넣기.

  3. 3

    마지막 판단은 내가: 직접 해보고 구체적으로 고칠 점 말하기.

  4. 4

    피드백은 「별로야」 대신 「3웨이브 핑크 총알이 너무 빨라」처럼 장소와 이유를 함께 말하세요.

  5. 5

    한 번에 하나만 고치게 하세요. 여러 개를 한꺼번에 바꾸면 무엇 때문에 좋아졌는지(나빠졌는지) 알 수 없어요.
